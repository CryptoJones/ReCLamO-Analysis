  **Rust fix folded in:** `examples/eval.rs::EvalCfg::to_model_profile` was creating the `ModelProfile` with `self.max_context` (CLI default 200K) and never pulling the TOML profile's `resident_kv`. The result: `route_by_size` was effectively disabled — the router saw a 200K budget and the plain-path check `est_tokens + 2K <= resident_kv` always passed for any context under 200K, which on a 1M-ctx model means *always*. The fix loads the TOML profile and uses `profile.resident_kv.unwrap_or(self.max_context)`. After the fix, the same Slice B settings produced the expected medium/large → harness routing. `cargo test --lib` still 59/59 green; the change is local to the eval example's profile construction.

  **Cross-model lesson:** the route-by-size logic is sound; the bug was that the eval example wasn't reading the TOML's `resident_kv`. The harness path on medium CAN work (Slice B's 9-subcall, 12-turn, 0.20 run) but model variance is large. Phase 7's full 8×3×2×2=96-cell grid will smooth that out. Two new lib tests cover the bypass + does_not_fit paths. `cargo test --lib` 61/61 green (was 59/59; +2). **Phase 5 numbers above are now invalidated** — re-running Phase 5 with honest arms is part of the Phase 6/7 work, not a separate task.
