- [x] **Phase 5e — transport hardening + lightning model diagnosis.** The "error decoding response body" that was keeping nemotron-3.5-lightning:free out of Phase 6 turned out to be **model-specific**, not transport-generic. nemotron-3-super-120b:free round-trips fine on the same rustls+reqwest stack; nemotron-3.5-lightning:free's first 8 response bytes are `b"\n         \n\n         \n..."` — literal leading whitespace before the JSON — and the chunked decoder chokes on it. `curl -i` on the same request gets an HTTP/2 200 with no Transfer-Encoding: chunked at all, so the response only looks malformed when the client negotiates HTTP/1.1. Hardening folded in: `reqwest` now pulls `gzip` + `http2` features (was `default-features = false` with only `json` + `rustls-tls`); the response body is now read via `Response::chunk()` instead of `.text()` / `.bytes()` so the harness doesn't depend on `BodyExt::collect` succeeding for whatever frame type comes back. Lightning still does not parse, but the streaming path is in place for any model that returns a body with mixed data + trailer frames. The `WireError.code` dead-code warning is also silenced via `#[allow(dead_code)]` (field is captured for forward compatibility, not read today).
